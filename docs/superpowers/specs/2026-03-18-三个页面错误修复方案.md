# 三个页面错误修复方案

## 问题描述

登录后的三个页面（帖子列表、聊天会话、活跃 Agents）都弹出"加载失败"错误弹窗。

## 根本原因分析

### 1. 后端路由配置错误（已修复）
- **问题**：`main.py` 中路由前缀重复，导致 404 错误
- **示例**：
  - `posts_router` 本身已有 `/api/v1/posts` 前缀
  - 在 `main.py` 中又加了 `/api/v1/posts` 前缀
  - 结果：`/api/v1/posts/api/v1/posts` → 404
- **状态**：✅ 已修复（移除重复前缀）

### 2. API 端点不匹配
- **问题**：前端调用的 API 路径与后端不一致
  - **活跃 Agents**：前端调用 `/api/v1/agents/me`，后端只有 `/api/v1/agents`
  - **帖子列表**：前端调用 `/api/v1/posts?limit=20&skip=0`，后端有 `/api/v1/posts` ✅
  - **聊天会话**：前端调用 `/api/v1/chat/sessions`，后端有 `/api/v1/chat/sessions` ✅

### 3. 响应格式不兼容
- **问题**：后端返回的数据格式与前端期望不一致
  - **Agents 列表**：
    - 前端期望：`Agent[]`
    - 后端返回：`{ agents: Agent[] }`
  - **帖子列表**：
    - 前端期望：`Post[]`
    - 后端返回：`Post[]` ✅
  - **聊天会话**：
    - 前端期望：`{ private_chats: ChatSession[], group_chats: ChatSession[] }`
    - 后端返回：`{ private_chats: [], group_chats: [] }` ✅

### 4. 缺少错误详细信息
- **问题**：前端错误弹窗只显示通用消息，没有具体错误信息
- **影响**：无法快速定位问题

## 修复方案

### 修复优先级
1. **高** - 添加 `/api/v1/agents/me` 端点（或修改前端）
2. **高** - 调整 Agents 列表响应格式
3. **中** - 改进前端错误提示
4. **中** - 确保后端服务正常运行

### 方案 1：后端方案（推荐）

**优点**：
- 保持前端代码简洁
- 符合 RESTful API 规范
- 后端统一处理响应格式

**实施方案**：

#### 1. 修复 Agents API 端点

**选项 A：添加 `/me` 端点**（推荐）
```python
# app/api/v1/agents.py
@router.get("/me")
async def list_my_agents(
    current_user: User = Depends(get_current_user),
    db: Session = Depends(get_db)
):
    """获取当前用户的 Agent 列表（兼容前端）"""
    agents = await get_user_agents(db, current_user.user_id)

    return {
        "code": 0,
        "data": [
            {
                "agent_id": agent.agent_id,
                "user_id": agent.user_id,
                "name": agent.name,
                "description": agent.description,
                "interests": agent.get_interests(),
                "autonomy_level": agent.autonomy_level,
                "is_active": agent.is_active,
                "last_active_at": agent.last_active_at.isoformat() if agent.last_active_at else None,
                "connected_at": agent.connected_at.isoformat() if agent.connected_at else None,
                "updated_at": agent.updated_at.isoformat() if agent.updated_at else None
            }
            for agent in agents
        ]
    }
```

**选项 B：修改现有 `/` 端点响应格式**
```python
# 修改 app/api/v1/agents.py 的 GET /
return {
    "code": 0,
    "data": [  # 改为数组而非 { agents: [] }
        {
            "agent_id": agent.agent_id,
            ...
        }
        for agent in agents
    ]
}
```

#### 2. 验证所有 API 端点
- 确保 `/api/v1/posts` 返回 `Post[]`
- 确保 `/api/v1/chat/sessions` 返回正确格式
- 确保所有端点都使用 `Depends(get_current_user)` 认证

### 方案 2：前端方案

**优点**：
- 不修改后端代码
- 快速验证

**缺点**：
- 不符合标准实践
- 维护成本高

**实施方案**：

#### 1. 修改 API 调用
```typescript
// frontend/src/api/agents.ts
export const getMyAgents = async (): Promise<Agent[]> => {
  const response = await api.get('/agents'); // 改为 /agents

  if (response.data.code === 0) {
    return response.data.data.agents || []; // 提取 agents
  }
  throw new Error(response.data.message || '获取 Agents 失败');
};
```

#### 2. 改进错误提示
```typescript
// frontend/src/pages/Dashboard.tsx, Feed.tsx, Chat.tsx
catch (error) {
  console.error('加载失败:', error);

  let errorMsg = '加载失败，请稍后重试';

  if (axios.isAxiosError(error)) {
    if (error.response) {
      // 服务器返回错误
      errorMsg = error.response.data?.message ||
                `错误 ${error.response.status}: ${error.response.statusText}`;
    } else if (error.request) {
      // 请求已发送但没有收到响应
      errorMsg = '无法连接到服务器，请检查后端是否运行';
    }
  }

  alert(errorMsg);
}
```

## 推荐方案

**采用方案 1（后端修复） + 方案 2 的错误提示改进**

理由：
1. 后端是数据源，应该提供标准的 API
2. 前端改进错误提示有助于调试
3. 两者结合提供最佳用户体验
